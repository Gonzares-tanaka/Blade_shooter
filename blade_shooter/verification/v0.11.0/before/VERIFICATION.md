# 0.10.0 検証報告（2026-11-09）

Webのスマホ操作を左手の相対ドラッグ移動＋右手のフリック攻撃へ変更しました。武器・敵・出現・ショット・移動倍率など戦闘バランスは0.9.0から変更していません。
変更前の原本は `verification/v0.10.0/before/` に保存しています。

## 担当と入力

ゲーム表示領域を左=移動、右=攻撃へ分割。接触開始位置から役割を決め、それぞれpointerIdを1本ずつ保持します。
境界を越えても離指まで担当を変えず、右手だけ先に触れても受け付けます。左右は互いの位置・速度・候補を変更しません。
担当が埋まっている側の余分な指は、その接触が終わるまで無視します。担当が空いても残った指を昇格させず、新しく触れた指だけが取得できます。

左担当は速度・方向にかかわらず相対移動のみ。触れた座標へワープせず、素早い回避でも攻撃しません。
右担当は剣・斧が左右、槍が上下フリック。攻撃はどちら向きでも自機の前方。指を離す前のmoveで発動し、事前タップは不要です。
右担当の変位は、誤方向・遅い移動・小さなブレ・再使用待ち中を含め、一切自機移動へ渡しません。従来の失敗フリックを移動へ戻す処理も削除しました。
同じ払いで再発動せず、静止または低速になってから新しい払いを判定します。離して触り直しても再入力可能。再使用待ち中に始まった払いは予約せず消費し、待ちの終了だけでは攻撃しません。

片方の正常なpointerupでは、その担当だけを解除。残った指は維持し、正常なlostpointercaptureで別の担当まで消さないようにしています。
キャンセル、予期しないcapture喪失、blur、pagehide、非表示、画面遷移、リサイズでは両担当・無視している指・攻撃候補・未消費入力を破棄します。
スクロール・ダブルタップ拡大・ピンチとの競合はtouch-action:noneとイベント抑止で抑えます。紹介ページの通常スクロールは残しています。

## 一か所の調整値

全値は `config.py: WEB_TOUCH`。座標はゲームの256×320pxへ変換し、CSS倍率・devicePixelRatioには依存しません。入力倍率drag_gain=1.2と既存の自機倍率1.3はフリックの距離に掛けません。

| 項目 | 初期値 |
|---|---|
| 境界 move_region_ratio | 左から50%（ゲームx=128）。境界上は攻撃側 |
| 距離 | 14px以上 |
| 速度 | 0.40px/ms以上（400px/秒） |
| 計測窓 | 90ms。速い動きの開始から計測 |
| 方向 | 剣・斧は横、槍は縦。軸から±35°、正負どちらも可 |
| 再判定 | 90msの静止、または120px/秒以下の移動 |
| 静止後の速度標本 | rAFで静止を観測後、直近1フレーム（16.67ms）から計測 |

ガイドの境界にも同じmove_region_ratioを使い、右側の薄い境界線・下部の3.5%の色・「斬撃エリア」表示を重ねています。pointer-events:noneで入力を遮らず、ゲームの描画や判定には混入しません。
ゲーム開始前と設定、Webの表示・紹介ページ、READMEの操作説明を左右分担へ統一しました。

## 確認結果

Python単体テスト88件、Nodeのジェスチャーテスト25件が成功しました。武器・戦闘の既存テストに加え、以下の担当・入力条件を確認しています。

- 左手の高速移動・任意方向・大きな移動で攻撃しない。
- 右手先行と左手先行の双方、左の余分な指がいても右は取得可能。
- 同時移動＋攻撃、候補の途中で左手や余分な指が動いても右の候補を維持。
- 左右の境界越え、双方の離指順、余分な指の無視、自動引継ぎなし、新接触による空き担当の取得。
- 全3武器の正負の方向、斜め許容、誤方向・短いタップ・小さなブレ・遅い動きの拒否。
- 一払い一回、低速/静止後の再判定、離指後の再入力、再使用待ちを予約しないこと。
- キャンセル・武器設定で両担当と候補を消去、重複/逆順のイベント、描画時計が進んだ場合の重複防止。

### Edgeの実ゲーム＋実マルチタッチ

Pyxel 2.9.9を実際に起動し、EdgeのCDPで複数の接触を同時に送りました。入力専用の場面では出現を止めて敵の干渉を除き、通常の自機移動・攻撃開始・再使用処理へ入力を通しています。

3武器とも右手だけで発動し、自機位置変化0。左手で高速移動しても攻撃せず、右手の攻撃と同時に左手を動かせました。
どちらかを先に離す、境界を越える、余分な指を置いてから担当を離す場合も、残った指の担当を維持。指の自動引継ぎはありません。
連続払いで重複せず、新しい払い・触り直しで再発動。再使用待ち中の払いが時間差で発動することもありません。
キャンセル、背景、画面遷移、接触中のリサイズで両担当を解除。幅320/768でも同じゲーム座標で判定し、ガイドの境界が50%に一致・縦横比0.8・横はみ出しなしを確認しました。
JavaScript例外0件。合成touchCancel時には公式ランタイムからnon-cancelableイベントへのpreventDefault警告が出ますが、解除結果は成功しました。

紹介ページは1440/768/390/320幅で確認。ページ内の実ゲームも、左ドラッグ・右フリック・一時停止を確認しました。

### WebKitとiPhone Safariの限界

WebKit 26.5をiPhone表示にし、複数のDOM PointerEventで同項目を確認しました。WASMは入力層の切り分け用に置き換え、capture APIもテスト用代替です。相対移動量・担当・攻撃イベントの確認であり、実機タッチやOSのcapture動作を確認したものではありません。
この入力層の試験は全項目成功、JavaScript例外0件です。

実Pyxelを含むWebKit試験も試しましたが、今回も公式CDNのPyodide v314.0.4上でfatal error / Unreachable codeとなり、タイトルへ到達できませんでした。
前版の独自コードを含まない公式最小サンプルでも同じ起動エラーを記録しています。入力層の成功をゲーム全体や実機Safariの成功とは扱いません。
iPhone実機には接続できないため、要求された5項目の実機確認は未実施です。Edge実マルチタッチとWebKit入力層での結果を分けて報告します。
