# 0.9.0 検証報告（2026-11-08）

事前タップ不要のフリックへ一本化し、ランスの穂先の攻撃・弾消し・表示を5pxから16px幅へ変更しました。
変更前のソース・素材・説明書は `verification/v0.9.0/before/` に保存しています。

## 入力と原因

従来は最初のタップと二度目の接触を待つ構成で、ドラッグから直接攻撃できませんでした。今回はタップ履歴、ダブルタップ、接触のやり直しを判定経路から削除。
ブレイド/アックスは左右、ランスは上下のフリック。方向の正負にかかわらず、武器は自機の前へ出ます。
武器別の方向を開始画面・設定・Webの常設表示・紹介ページへ反映し、操作方式の選択は廃止。武器選択と54秒の固定比較コースは残しました。

### 判定の設定値

全設定は `config.py: WEB_TOUCH`。距離は256×320のゲーム座標へ正規化し、CSS倍率・devicePixelRatioには依存しません。drag_gain=1.2と自機速度倍率1.3は判定に掛けません。

| 項目 | 値 |
|---|---|
| 距離 | 14px以上 |
| 速度 | 0.40px/ms以上（400px/秒） |
| 計測窓 | 90ms以内。触れ始めではなく速い動きの開始から計測 |
| 方向 | 武器の横/縦軸から±35°、正負どちらも可 |
| 再準備 | 90msの静止、または120px/秒以下のゆっくりした移動 |
| 静止後の速度標本 | rAFで静止を観測後、直近1フレーム（16.67ms）から計測 |
| 不成立の保留移動 | 最大125px/秒で滑らかに移動へ戻す。離指・キャンセルで残りは破棄 |

通常のドラッグは即座に相対移動として渡します。速く軸に合う候補は変位を保留し、距離・平均速度が成立したpointermoveで一度だけ攻撃します。指を離すのは待ちません。
成立した払いの変位は移動へ戻さず、自機の飛びを防ぎます。同じ高速ストロークは再使用可能になっても再発動しません。
一瞬止めるかゆっくり動かしてから、指を置いたまま新しい払いで次の攻撃が出ます。再使用待ち中に始めた払いは予約せず消費し、待ち終了後に勝手に攻撃しません。
キャンセル、非表示、blur/pagehide、設定遷移、リサイズでは候補と保留移動・未消費入力を破棄。保持中の物理キーも設定へ持ち越しません。
ゲーム領域のtouch-action:none、スクロール・ダブルタップ拡大の抑止は維持しています。

実ブラウザで、イベント時刻より描画タイマーが先へ進む場合を確認しました。タイマーで元イベント時刻を書き換えないようにし、遅着イベントの欠落と同一ストロークの誤った再準備を修正。その回帰テストも追加しました。

## ランスの幅と維持した性能

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 穂先の横幅 | 5px | 16px（自機の見た目幅と同じ） |
| 最大リーチ | 94px | 94px |
| 威力 | 32 | 32 |
| 準備 / 有効 / 戻り | .055 / .160 / .200秒 | 同じ |
| 再使用 / ショット停止 | .82 / .415秒 | 同じ |

自機を突進させず、長さ28pxの穂先を46→94pxへ直線的に突き出します。描画と判定は同じ武器の姿勢・幅を使い、敵への攻撃と敵弾の消去の両方へ16pxを適用。
Image0の(208,0)を28×16へ拡張し、穂先が全幅を占める見た目にしました。旧5行を残し、空いていた下11行だけへ追加しました。
原本 `assets/blade.pyxres` をPyxel Editorで編集可能。全既存画素、Sound/Music、タイルマップ、52色の順序を保持しています。
ブレイド・アックスと、ランスの幅以外の全性能は変更前と一致することをテストしました。
攻撃中のショット停止、戻り終了後の射撃再開、移動可能、近接無敵なし、敵一体への一振り一回、発射済みの敵弾が残る仕様を維持。
矢印＋Z、GKDの十字キー＋A、START、SELECT終了、Bの武器設定も維持しています。

## 確認結果

Python単体テスト88件、Nodeジェスチャーテスト16件が成功しました。
ランスについては、従来幅では外れる横15pxの敵に命中し、横10pxの敵弾を消し、範囲外の横12pxの弾は残すことを確認（敵・弾の半径込み）。
全武器で全攻撃フェーズ中の移動、ショット停止、再使用待ち中の射撃再開、無敵なし、一振り一回を確認しています。

### 実ゲームと比較コース

自動入力は移動と近接入力のみ。HP回復・無敵化・弾の強制消去は使いません。人のプレイ感の評価とは区別します。

| 武器 | クリア | 残HP | 近接回数 | 近接撃破 | 弾消し |
|---|---:|---:|---:|---:|---:|
| ブレイド | 54.000秒 | 2 | 30 | 29 | 28 |
| アックス | 54.000秒 | 3 | 27 | 31 | 13 |
| ランス | 54.000秒 | 3 | 27 | 26 | 16 |

実Pyxel 2.9.9・60fpsでも3武器を各54秒、描画・音声付きで通し、上表と一致しました。3本の実測は165.06秒（画面保存込み）。
ランスの弾消しは前版の同種の自動入力11発から16発へ増加。幅によって操縦の経路も変わるため、厳密な同一入力の優劣比較ではありません。
静止・自動ショットのみは8.617秒で撃墜。比較コースの出現表・HP・弾速は武器間で同じです。

### ブラウザ

Edgeの実PyxelとCDP実タッチで3武器を確認：ドラッグ中から事前タップなしで発動、指を離す前に攻撃開始、攻撃用の変位で自機位置変化なし。
同じ払いの追加moveで発動を重複させず、指を置いたまま再使用後の新しい払いで発動。誤方向では攻撃せず、約27°の斜め入力は成立。
touchCancel、blur、pagehide、非表示→表示の途中候補を破棄。幅320/768でも同じゲーム座標の払いが成立し、ゲーム縦横比0.8・横はみ出しなしを確認しました。

WebKit 26.5のiPhone表示では**入力層のみ**を切り分けて同項目を確認しました。PointerEventは実マウスで生成しており、実iPhoneのタッチではありません。相対移動が払いへ混入しないことも確認、JavaScript例外0件です。
実Pyxelを含むWebKit試験では、公式CDNのPyodide v314.0.4上でfatal error / Unreachable codeとなり、タイトルに到達できませんでした。独自ゲーム・入力を含まない公式64×64の対照試験でも、Pythonの入口には到達するもののpyxel.init完了前に同じエラーで停止しました。この環境でSafariのゲーム本体が動くことは確認できていません。入力層のみの成功をゲーム全体や実機Safariの成功とは扱いません。
